At a glance

Two front ends, one API

Cupidate is a member app and a staff admin panel, both served by a single Express API over MongoDB. Every figure below is countable in the source — none of them are traffic numbers.

What it does

Six ways to meet someone

Cupidate is built around proximity rather than an endless swipe deck. You see who is genuinely nearby, and you have more than one way to open a conversation.

Nearby discovery

A radar and a map of people inside your chosen radius, ranked by distance. The server returns a rounded distance rather than a position.

2dsphere index$geoNearRadius filter

Signals

Send a signal to someone nearby with an optional note. They can accept, decline or save it — accepting opens a chat and adds them to your contacts.

Accept · decline · saveOpens a chat

Floating bottles

Cast a message into the Void for strangers to find. Choose who can see it by gender and by city, state or a custom area. Bottles expire after seven days.

7-day expiryAudience filtersReplies open a chat

Anonymous chat

Talk under a generated alias first. Identities unmask only when both people choose to reveal — revealing on your own just lets the other person know.

Generated aliasesMutual consent

Real-time messaging

Chat over Socket.io with typing indicators, read receipts and photo messages, plus push notifications when the app is in the background.

TypingRead receiptsMedia

AI helper

Four Claude-powered tools: write your bio, talk through a conversation with a coach, get a reply suggested in chat, and verify your photos show one real person.

What I built

Engineering highlights

The parts of Cupidate that took the most careful work.

  1. 01Two front ends on one API

    A React Native app for members and a React admin panel for staff, both served by a single Express API — 84 REST endpoints across 12 Mongoose models, with one shared authentication layer.

  2. 02Geospatial discovery pipeline

    Discovery runs as a $geoNear aggregation against a 2dsphere index, projecting a rounded distance and applying each member's visibility setting, block list and gender preference inside the query — before any result leaves the server.

  3. 03Real-time layer on the same identity

    Socket.io authenticates its handshake with the same JWT as the REST API, and verifies chat membership on every join, so a socket can only subscribe to conversations it belongs to. Typing, read receipts and live location share the connection.

  4. 04Anonymous chat with consent-gated reveal

    Per-chat aliases carry no link back to the real profile. The server releases both profiles only once both participants have revealed; a one-sided reveal just emits a prompt to the other side.

  5. 05Five-level staff hierarchy

    Super admin, admin, agent, worker and member, enforced by layered middleware: a role check, per-action permissions, and a location scope that narrows every staff query down to the cities that person actually covers.

  6. 06AI features on Claude Haiku 4.5

    Four endpoints behind the Anthropic SDK — bio generation, a conversation coach, in-chat reply suggestions, and a vision call that assesses whether a member's photos show one real, non-AI-generated person and returns structured JSON.
